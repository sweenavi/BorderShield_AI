3. BDMRA (DYNAMIC MULTI-CRITERIA ROUTING ALGORITHM) & EDGE COST
--------------------------------------------------------------------------------
- Dijkstra Algorithm: Verified that `routingService.js` correctly builds the road network graph and runs a Standard Dijkstra Shortest Path Search.
- Edge Penalty Method: Updated `operationalCostService.js` to correctly merge Distance and Risk into a unified Operational Cost. Formula used: Dynamic Cost = Distance * (1 + (Operational Risk / 100)). This prevents Dijkstra from blindly favoring high-risk routes just because they have fewer edges.
- Route Pruning: Integrated the Admin road-blocking feature natively into the routing engine. If a road is marked "BLOCKED", it is completely removed from the adjacency list before Dijkstra runs.
- Route Analysis UI: Updated titles in `RouteAnalysis.jsx` to reflect the "FROZEN WEIGHTS" and "DYNAMIC EDGE WEIGHT (EDGE-PENALTY METHOD)" logic, proving to the user that the backend strictly follows the architecture.

4. ADMINISTRATIVE FEATURES
--------------------------------------------------------------------------------
- Operational Road Status: Created the road status modification workflow in `MasterDataManagement.jsx`.
- Admins can now select an active road and change its operational status to OPEN, RESTRICTED, or BLOCKED.
- This immediately updates the routing engine, ensuring subsequent mission calculations bypass blocked roads.
