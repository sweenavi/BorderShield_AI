================================================================================
BORDERSHIELD AI - ROLE-BASED FEATURES & TECHNOLOGY STACK
================================================================================

This document outlines the primary roles in the system, detailing their features,
the step-by-step usage workflows, expected outcomes, the underlying technology, 
and how each feature integrates with the frozen source documentation.

--------------------------------------------------------------------------------
ROLE 1: MISSION PLANNER (OFFICER)
--------------------------------------------------------------------------------
Purpose: To plan, evaluate, and authorize secure logistical routes across the 
Leh-Ladakh-Siachen sector using the AI-driven Multi-Criteria Routing framework.

1. Planner Dashboard (`PlannerDashboard.jsx`)
   - Function: Provides a high-level operational overview of active missions and overall system status.
   - Steps to Use: Upon logging in as an Officer, the user lands directly on this dashboard. They can visually inspect recent system alerts and active route operations.
   - Expected Outcome: The Officer gains immediate situational awareness of current operations before planning new missions.
   - Tech Stack: React Router DOM (navigation layout), Lucide React (icons), native CSS Grid for responsive widgets.

2. Operational Map (`OperationalMap.jsx`)
   - Function: A full-screen interactive map displaying all nodes (Bases, Checkposts, Relief Posts) and geographical routing.
   - Steps to Use: The user navigates to the "Map" tab. They can pan and zoom across the sector to inspect nodes and active route vectors.
   - Expected Outcome: Visual confirmation of geographical node placement and potential route bottlenecks.
   - Tech Stack: `react-leaflet`, OpenStreetMap tiles. Renders calculated path vectors outputted by the backend algorithms.

3. Create Mission (`CreateMission.jsx`)
   - Function: The central input terminal for initiating a new operational mission.
   - Steps to Use: 
     1. Enter the starting Base/Node (Source).
     2. Enter the destination Node.
     3. Select the Mission Type (e.g., Convoy, Search & Rescue).
     4. Set Priority and Vehicle parameters.
     5. Click "Calculate Safe Route".
   - Expected Outcome: The system triggers the routing algorithms and transitions the user to the Route Analysis view containing computed paths.
   - Tech Stack: React State (Controlled forms), integrated dynamically with `routingService.js` (BDMRA Engine).

4. Route Analysis & Evaluation (`RouteAnalysis.jsx`)
   - Function: The core decision-support interface showing the Recommended Route alongside Alternative Routes. Displays a complete mathematical breakdown of Weather, Terrain, and Road risks.
   - Steps to Use: 
     1. Review the "Recommended Route" distance, ETA, and Operational Risk.
     2. Scroll through the MCREE panel to examine individual raw values and standardized risks (e.g., Avalanche Risk, Snowfall).
     3. Review the BDMRA section to see the step-by-step path selected.
     4. Compare the recommended route against generated alternative routes.
     5. Click "Approve Mission" or "Generate Report".
   - Expected Outcome: The Officer makes a fully informed, data-driven decision on whether to proceed with the mission. 
   - Tech Stack: React components iterating over complex nested JSON arrays generated by the backend engine.
   - Documentation Link: Directly implements the UI representation of the Multi-Criteria Risk Evaluation Engine (MCREE) from `SOURCE/Standardizarion Doc.txt` and the routing logic from `BDMRA2.txt`.

5. Mission Report (`MissionReport.jsx`)
   - Function: A formal, print-ready tactical summary of the approved mission and its recommended route.
   - Steps to Use: After approving a route, click the "Print Mission Report" button. The browser print dialog will open automatically.
   - Expected Outcome: A formatted physical or PDF document containing all mission parameters, risk analyses, and operational node sequences for field execution.
   - Tech Stack: Native browser printing API (`window.print()`), responsive CSS `@media print` queries for clean formatting.

--------------------------------------------------------------------------------
ROLE 2: ADMINISTRATOR (ADMIN)
--------------------------------------------------------------------------------
Purpose: To manage system health, oversee high-priority mission sign-offs, and 
dynamically modify master road statuses during emergencies or severe weather events.

1. Admin Dashboard (`AdminLayout.jsx` / `AdminDashboard.jsx`)
   - Function: The command center for administrators showing total active personnel, critical alerts, and global system health.
   - Steps to Use: Log in using Admin credentials. Monitor the high-level widgets for any anomalies.
   - Expected Outcome: Real-time oversight of system usage and infrastructure status.
   - Tech Stack: React Router nested layouts and modular React components.

2. Master Data Management (`MasterDataManagement.jsx`)
   - Function: Allows admins to modify the status of any road segment in real-time.
   - Steps to Use:
     1. Navigate to Master Data -> Roads.
     2. Select a specific road (e.g., R060).
     3. Change its status to OPEN, RESTRICTED, or BLOCKED.
     4. Provide an operational reason and click "Save".
   - Expected Outcome: The road's operational status is instantly updated globally. If marked BLOCKED, it visually updates to red/blocked on maps, and future routing calculations will avoid it.
   - Tech Stack: React State connected to `roadStatusService.js` utilizing a Singleton pattern for global state mutation.
   - Documentation Link: Ties directly into the dynamic graph pruning logic of `BDMRA1.txt` / `BDMRA2.txt` (a blocked road is mathematically removed from the Dijkstra adjacency list before pathfinding).

3. Mission Authorization (`MissionAuthorization.jsx`)
   - Function: A secure queue for reviewing high-priority missions that exceed standard risk thresholds and require manual sign-off.
   - Steps to Use: 
     1. Open the Authorization queue.
     2. Select a pending "Emergency" or "High-Risk" mission.
     3. Review the MCREE risk scores.
     4. Click "Approve" or "Deny".
   - Expected Outcome: The mission is authorized for field execution or rejected, preventing unsafe deployment.
   - Tech Stack: React list rendering and state management.

4. System Logs (`SystemLogs.jsx`)
   - Function: Provides an immutable, chronological audit trail of all critical system actions.
   - Steps to Use: Open the Logs tab. Filter or scroll to view recent actions (e.g., who approved a mission or who blocked a road).
   - Expected Outcome: Complete transparency and accountability for system actions.
   - Tech Stack: Formatted chronological list rendering.

--------------------------------------------------------------------------------
BACKEND ARCHITECTURE & ALGORITHMS (Documentation Driven)
--------------------------------------------------------------------------------
The backend algorithms are purely functional JavaScript modules that strictly adhere to the frozen source text files.

1. Multi-Criteria Risk Evaluation Engine (MCREE)
   - File: `riskService.js`
   - Role: Converts raw JSON data (Weather, Terrain, Road) into standardized 0-100 risk scores.
   - Tech: Piecewise mathematical threshold functions and AHP (Analytical Hierarchy Process) weighted averages.
   - Source Doc: `SOURCE/Standardizarion Doc.txt`

2. BorderShield Dynamic Multi-Criteria Routing Algorithm (BDMRA)
   - File: `routingService.js`
   - Role: Computes the safest and most efficient path from Source to Destination.
   - Tech: Standard Dijkstra Shortest-Path Algorithm combined with Priority Queue data structures.
   - Source Doc: `SOURCE/BDMRA1.txt`, `SOURCE/BDMRA2.txt`

3. Dynamic Edge-Penalty Method
   - File: `operationalCostService.js`
   - Role: Merges Physical Distance with MCREE Operational Risk to produce the final "Edge Weight" fed into Dijkstra.
   - Tech: Exponential/linear penalty mathematics (Dynamic Cost = Distance * (1 + (Risk / 100))).
   - Source Doc: `SOURCE/BDMRA2.txt`
